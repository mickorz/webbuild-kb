# E01 书架管理探索笔记

日期：2026-11-28
方式：脚本化探索（login-capture 刷新登录态 + capture-steps fillenter 步骤 + DOM probe）

## 控件盘点（当前账号：1 本书《全球高武》）

| 控件 | 选择器/位置 | 探索结果 |
|------|-------------|----------|
| 搜索框 | `input[type=search]`，placeholder「搜索作品…」 | ✅ 已探索 |
| 排序 / 筛选 / 分页 | 未渲染 | 单书账号下无这些控件，无法探索（待多书账号或造数后补） |
| 书籍操作 | 导出 / 编辑（`.bc-action`）、打开（`.bc-open`，悬停出现）、创作助手（`.asst-launch`） | ✅ 打开已探索 |
| 其他 | 新建作品、刷新余额、CDK 兑换、个人中心、中/EN、深色主题、ttest 收藏圈（`lfav-circle`） | 未探索 |

## 关键发现

1. **搜索是纯前端过滤，不产生任何 API**：fill + Enter 搜「全球」/「zzz不存在的书名」，网络层面零新请求。书籍数组已在归档中全量录制，因此离线回放的搜索天然可用。
2. **线上与离线行为逐字一致**：线上搜「zzz」后《全球高武》仍然可见（无空态提示词）——即搜索框在此交互方式下没有可观测的过滤效果。离线回放表现完全相同。E01 场景按线上真实行为断言（可见性不变），而不是想当然的「应隐藏」。
3. **书籍详情（`.bc-open`）的 API 已随本次补采刷新为最新版本**（chapters/characters/outlines 等 +5 条新 FIFO 版本）。
4. 探索期间归档 347 → 381 条（页面加载类 API 因时间戳字段滚动产生新 FIFO 版本，属正常增长）。

## 工具沉淀

- capture-steps 新增 `fill:` / `fillenter:` 步骤（选择器=值，按最后一个 `=` 拆分，属性选择器如 `input[type=search]` 可直接用）
- 回归 runner 新增 `{fill, value, enter, expectText, expectTextAbsent}` 步骤类型，支持操作后立即断言界面状态
